# TaskBoard Review Fix

TaskBoard のレビュー指摘対応では、指摘をそのまま機械的に反映せず、既存仕様、設計、テスト方針に照らして妥当性を確認してから修正する。対応範囲はレビュー指摘に必要な最小限に絞り、無関係な改善やリファクタリングを混ぜない。

## このSkillの役割

このSkillは、レビュー済みPRの指摘取得から修正をpushし、再レビュー可能な状態にするまでを担当する。修正後の再レビューは `taskboard-review` の対象にする。

基本の流れ:

1. PRの指摘取得
2. 指摘の妥当性確認
3. 修正
4. テスト
5. `npm run verify`
6. コミット
7. push
8. 再レビュー依頼

GitHub操作は `docs/engineering/github-workflow.md` のコマンド利用方針に従う。

## 作業開始

1. `git status --short --branch` で現在のブランチと未コミット変更を確認する。
2. 対象PR番号、対象ブランチ、未対応のレビュー指摘を特定する。
3. 作業ブランチが対象PRのheadと違う場合は、`docs/engineering/github-workflow.md` に従って適切なブランチへ切り替える。
4. ユーザーの未コミット変更がある場合は、勝手に戻さず、レビュー指摘対応に必要な差分だけを扱う。

## 指摘取得

GitHub上のPRレビューコメント、通常コメント、チェック結果を確認する。

確認すること:

- 未対応の指摘は何か
- blocker、major、minor、nit のどれに近いか
- 指摘対象のファイルと行はどこか
- 修正要求なのか、質問・確認なのか
- CIや検証の失敗が含まれているか

## 妥当性確認

指摘ごとに、修正前に次を確認する。

- `AGENTS.md`: 作業ルール、検証ハーネス、PR作成時の記載事項
- `docs/ARCHITECTURE.md`: 現在の構成、主要ファイルの責務、レイヤー分離方針
- `docs/README.md`: 参照すべきドキュメントの一覧
- `docs/product/todo-app.md`: TODOアプリの仕様、バリデーション、テスト観点
- `docs/engineering/coding-style.md`: TypeScript、React、配置、命名、テスト方針
- `docs/engineering/github-workflow.md`: ブランチ、コミット、Issue、PRの運用ルール

Next.js 関連の実装を変更する場合は、`AGENTS.md` の Next.js agent rules に従い、`node_modules/next/dist/docs/` の該当ドキュメントも確認する。

指摘が仕様や設計と矛盾する場合は、無理に修正せず、理由を整理してユーザーに確認する。判断が分かれる場合は、修正案と見送り案のメリット・デメリットを短く示す。

## 修正方針

- レビュー指摘に直接関係する最小範囲だけを修正する。
- 指摘対応と無関係な整形、依存追加、設計変更を混ぜない。
- 既存の責務分離を守り、ビジネスロジックを React コンポーネントへ寄せすぎない。
- `any` や型エラー回避目的の型アサーションは避ける。
- レビューコメントが誤解に基づく場合は、コード変更ではなくPRコメントで根拠を説明する選択肢も検討する。

## テストと検証

ユーザーから見える振る舞い、バグ修正、仕様変更に関わる指摘へ対応した場合は、必要なテストを追加または更新する。

コード、設定、依存関係、検証ハーネスを変更した場合は、原則として次を実行する。

```bash
npm run verify
```

`npm run verify` を実行できない場合は、理由と残るリスクをPRコメント、PR本文の更新、または完了報告に明記する。

## 差分確認

push前の差分確認、コミット、pushは `docs/engineering/github-workflow.md` に従う。

確認観点:

- レビュー指摘に関係しない変更が含まれていないか
- すべての対応済み指摘に、コード変更、テスト、または説明のいずれかで答えているか
- 追加・更新したテストが指摘内容に対応しているか
- `npm run verify` の結果を説明できるか

## 再レビュー依頼

push後は、対応内容と検証結果をPR上で分かるようにする。必要に応じてレビューコメントへ返信し、再レビューを依頼する。

完了報告では次を簡潔に伝える。

- 対応した指摘
- 修正内容
- 変更した主要ファイル
- 追加または更新したテスト
- 実行した検証
- 残っている問題
